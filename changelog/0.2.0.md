# [0.2.0] — 2026-07-17

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/).

## Добавлено

- **Модуль `doc-engine-jodconverter`.** Быстрая PDF-конвертация через пул долгоживущих LibreOffice-процессов (JODConverter): **`JodDocumentConverter`** с настраиваемыми размером пула, портами и реакцией на уже запущенный офисный процесс; авто-конфигурация подключает пул, когда модуль на classpath. Зависит только от `doc-engine-api`.
- **Потоковый вывод.** **`generateTo(OutputStream)`** и **`generateToFile(Path)`** — без буферизации всего результата в памяти; запись в файл на другой файловой системе прозрачно откатывается к копированию.
- **Жизненный цикл.** `DocumentEngine` и `TempFileManager` стали **`AutoCloseable`**; `close()` каскадно закрывает конвертеры, не трогая коллабораторов, которыми управляет контейнер.
- **DX.** Билдер **`GenerationOptions`**, фабрики **`TemplateReference.ofBytes/ofStream`**, фабричные методы `DocumentEngineBuilder` — пользователю больше не нужны импорты internal-классов; `TemplateReference` распечатан (non-sealed) для собственных resolver-ссылок.
- **Spring.** Метаданные конфигурации для свойств `doc-engine.*` — автодополнение и описания в IDE.
- **Сборка и CI.** Windows-job (пути завершения soffice-процессов); релиз гейтится LibreOffice-интеграционными тестами, наличием changelog-файла версии, содержимое которого становится release notes (draft-релиз создаётся до deploy), и тем, что тег лежит на `master`; maven-enforcer (JDK 25, Maven ≥ 3.8.4); Maven Wrapper 3.9.16; порог покрытия JaCoCo 75% на модуль; воспроизводимые артефакты (`outputTimestamp`); javadoc-линт в релизном профиле; таймауты и concurrency в CI; пиновка actions на commit-SHA; Dependabot с группировкой minor/patch; dependency-review для PR; `Automatic-Module-Name` в манифестах.

## Изменено

- **Breaking — пакеты:** базовый пакет переименован `com.example.docengine` → `io.github.nikolaynn.docengine`.
- **Breaking — модули:** публичный API и SPI выделены в новый артефакт **`doc-engine-api`** (реализаторам SPI больше не нужна зависимость от core); `DocumentEngineBuilder` переехал в пакет `io.github.nikolaynn.docengine.core`.
- **Breaking — платформа:** реактор переведён на **Java 25** и **Spring Boot 4.1** (было: Boot 2.7); авто-конфигурация стартера зарегистрирована через `AutoConfiguration.imports`.
- **JXLS 2.x → 3.1.0:** рендер переведён на **`JxlsPoiTemplateFillerBuilder`**; вычищены логирующие бэкенды, протекавшие транзитивно из JXLS 2.x.
- Рендер JXLS выполняется в один проход, без повторного парсинга воркбука POI.

## Исправлено

- **LibreOffice:** усилено управление процессом — снапшот дерева процессов перед kill (soffice-лаунчер и его `soffice.bin`), ретраи удаления файлов после асинхронного освобождения хэндлов на Windows, stderr декодируется в нативной кодировке платформы.
- Null-значения в данных запроса и engine hints больше не роняют рендер.
- `DefaultTempFileManager` создаёт корневой temp-каталог в конструкторе — устранён сбой при первом использовании.
- Ресурсы конвертера освобождаются на всех путях очистки; билдер без единого сконфигурированного движка шаблонов падает при создании, а не при первом `generate()`.
- **`TemplateReference.BytesRef`** сравнивается по содержимому (value equality).
- Дефолт `doc-engine.cleanup-on-shutdown` выровнен с метаданными конфигурации (итог: `true`).

## Безопасность

- Миграция на JXLS 3.1.0 сняла CVE-пины транзитивных зависимостей 2.x-эры; JEXL обновлён до **3.7.0** (SECURE-дефолты, усиленная изоляция RESTRICTED-песочницы — JEXL-462).
